.. _dsdp:

=====================================================
Differential Semidefinite Programming (DSDP)
=====================================================

.. module:: Irene.dsdp

Overview
--------

The DSDP framework extends the Lasserre moment-SOS hierarchy to optimization
problems where the variables include transcendental functions (exponentials,
trigonometric, hyperbolic, logarithmic) by encoding their algebraic
differential equations (ADEs) as algebraic constraints in the quotient ring.

Instead of approximating :math:`e^x` by a truncated Taylor series, DSDP
introduces an auxiliary variable :math:`y` representing :math:`e^x` and
enforces the ADE relation :math:`y \cdot z = 1` (where :math:`z = e^{-x}`)
as an algebraic constraint. This lifts semialgebraic optimization to
differential-algebraic optimization, where the moment hierarchy's convergence
guarantees apply directly.

Multi-Derivation Framework
--------------------------

**Motivation.** A single derivation operator :math:`D_x` suffices for
univariate ADE systems — tan-ADE, exp-ADE, sin/cos lifts all require
only one independent variable. For *holonomic* systems with multiple
independent variables, each partial derivative :math:`\partial/\partial x_i`
defines a distinct derivation on the generator ring, requiring independent
diff_maps.

**Mathematical foundation.** Let :math:`R = \mathbb{R}[x_1,\ldots,x_n,
g_1,\ldots,g_m]` be the differential polynomial ring with commuting
derivations :math:`\{D_1, \ldots, D_k\}` where each :math:`D_i` is a
Leibniz derivation:

.. math::

    D_i(f \cdot g) = D_i(f) \cdot g + f \cdot D_i(g)

Each derivation is specified by its action on generators:

.. math::

    D_i(x_j) = \delta_{ij} \quad \text{(Kronecker delta, usually)}
    D_i(g_j) = p_{ij}(x_1,\ldots,x_n, g_1,\ldots,g_m)

The ADE relations :math:`D_i(g_j) - p_{ij} = 0` are encoded as difference
polynomials in the quotient ring :math:`R / I`, where :math:`I` is the ideal
generated by all ADE relations and algebraic invariants (e.g.,
:math:`s^2 + c^2 - 1 = 0` for sin/cos).

**Symbol naming.** Derivative symbols use distinct prefixes based on the
derivation variable to prevent Groebner cross-contamination:

=========== ================== =====================================
Derivation  Symbol prefix      Example symbols
=========== ================== =====================================
:math:`D_x` ``dx_``            ``dx_x, dx_s, dx_c``
:math:`D_y` ``dy_``            ``dy_y, dy_L, dy_v``
(default)   ``d_``             ``d_x, d_s, d_c`` (backward compat)
=========== ================== =====================================

Crucially, ``dx_y`` from :math:`D_x` and ``dy_y`` from :math:`D_y` are
*distinct symbols*, preventing the Groebner basis from conflating
derivative relations from different derivations.

**KKT injection.** The differential KKT conditions are computed with
respect to a specific derivation:

.. math::

    \frac{\partial L}{\partial x_j} \Big|_{D_i} = D_i(L)(x_j) = 0

where :math:`L = f - \sum \lambda_\ell \cdot g_\ell` is the Lagrangian.

Multi-Derivation API
--------------------

**Registering derivations:**

.. code-block:: python

    # Single derivation (backward compatible)
    dsdp = DSDPRelaxations([x, y], diff_map={x: 1, y: y})
    # → diff_maps = {'x': {x: 1, y: y}}

    # Multi-derivation via set_derivation
    dsdp.set_derivation({x: 1, y: y}, wrt='x')
    dsdp.set_derivation({y: 1, u: v, v: -v**2}, wrt='y')

    # Multi-derivation via constructor kwarg
    dsdp = DSDPRelaxations([x, y, u, v], diff_maps={
        'x': {x: 1, y: y},
        'y': {y: 1, u: v, v: -v**2}
    })

**Building ADE relations with derivation-aware prefixes:**

.. code-block:: python

    tmp = DSDPRelaxations([x, s, c])
    dx_syms, dx_rels, dx_gens = tmp.build_ade_relations(
        {x: 1, s: pi*c, c: -pi*s}, wrt='x'
    )
    # dx_syms = {x: dx_x, s: dx_s, c: dx_c}
    # dx_rels = [dx_x - 1, dx_s - pi*c, dx_c + pi*s]

    dy_syms, dy_rels, dy_gens = tmp.build_ade_relations(
        {y: 1, L: v, v: -v**2}, wrt='y'
    )
    # dy_syms = {y: dy_y, L: dy_L, v: dy_v}

**Differentiating with a specific derivation:**

.. code-block:: python

    # D_x(v * y)  using diff_maps['x']
    result = dsdp.differentiate(v * y, x, wrt='x')

    # D_y(u * v) using diff_maps['y']
    result = dsdp.differentiate(u * v, y, wrt='y')

    # Default (first registered derivation)
    result = dsdp.differentiate(expr, var)  # uses first diff_maps entry



Holonomic System Example
-------------------------

Minimize :math:`x \cdot \log(y) + y \cdot \sin(\pi x) \cdot \cos(\pi x)`
on :math:`[-1, 1]^2`, using ADE lifts for :math:`\log(y)` and
:math:`\sin(\pi x), \cos(\pi x)` with independent derivations :math:`D_x`
and :math:`D_y`.

.. code-block:: python

    from sympy import symbols, pi
    from Irene.dsdp import DSDPRelaxations

    # Domain variables and lifted functions
    x, y, s, c, L, v = symbols('x y s c L v')

    # Build D_x relations for sin/cos lift
    tmp = DSDPRelaxations([x, s, c])
    dx_syms, dx_rels, dx_gens = tmp.build_ade_relations(
        {x: 1, s: pi*c, c: -pi*s}, wrt='x')

    # Build D_y relations for log lift: D_y(L)=v, D_y(v)=-v², y*v=1
    tmp2 = DSDPRelaxations([y, L, v])
    dy_syms, dy_rels, dy_gens = tmp2.build_ade_relations(
        {y: 1, L: v, v: -v**2}, wrt='y')

    # Merge all generators and constraints
    all_gens = (list(dx_syms.values()) + list(dy_syms.values())
                + [x, y, s, c, L, v])
    all_rels = dx_rels + dy_rels + [s**2 + c**2 - 1, y*v - 1]

    dsdp = DSDPRelaxations(
        all_gens, relations=all_rels,
        diff_maps={
            'x': {x: 1, s: pi*c, c: -pi*s},
            'y': {y: 1, L: v, v: -v**2}
        },
        original_gens=[x, y, s, c, L, v],  # don't box derivative symbols
        box_size=1
    )
    dsdp.SetObjective(x*L + y*s*c)
    lb = dsdp.solve(order=2)


Theory: Why Multi-Derivation Matters
-------------------------------------

**Without multi-derivation** (single diff_map only), encoding a
holonomic system requires manual derivative symbols in every relation.
For the log-lift :math:`D_y(L) = v, D_y(v) = -v^2`, one would need to
manually add symbols ``dL``, ``dv`` and relations ``dL - v = 0``,
``dv + v^2 = 0`` as algebraic constraints — bloating the generator
list and the Groebner basis.

**With multi-derivation**, ``build_ade_relations`` handles all ADE
symbol creation and relation generation. The KKT injection correctly
selects which derivation to use when differentiating the Lagrangian,
and the distinct symbol prefixes prevent the Groebner basis from
conflating derivative relations across derivations.

**Generator count reduction.** A typical holonomic P7 problem goes
from 8 domain + 8 manual-derivative = 16 generators to
8 domain + 3 D_x-derivatives + 3 D_y-derivatives = 14 generators
(~12% reduction). The Groebner basis is cleaner because derivative
symbols from :math:`D_x` never interact with those from :math:`D_y`.



ADE Encoding Theory
-------------------

Each transcendental function :math:`g(x)` is replaced by an auxiliary
generator :math:`y_g` satisfying an algebraic differential equation:

============= ==================== =========================================
Function      ADE                  Algebraic encoding
============= ==================== =========================================
:math:`e^x`   :math:`y' = y`       :math:`y \cdot z = 1` (with :math:`z = e^{-x}`)
:math:`\log x`:math:`xy' = 1`      :math:`y \cdot v = 1, D(v) = -v^2`
:math:`\sin x`:math:`y'' = -y`     :math:`s^2 + c^2 = 1, D(s) = c, D(c) = -s`
:math:`\tan x`:math:`y' = 1 + y^2` :math:`D(u) = 1 + u^2`
:math:`\sinh x` :math:`y'' = y`    :math:`ch^2 - sh^2 = 1, D(sh) = ch, D(ch) = sh`
============= ==================== =========================================

These relations form the ideal :math:`I` and are enforced via Groebner
reduction in ``ReduceExp()``. The ``build_ade_relations()`` method
automates the creation of derivative symbols and the corresponding
ADE relations from a derivation map.



Differential KKT Conditions
----------------------------

The differential KKT injection differentiates the Lagrangian

.. math::

    L(x, \lambda) = f(x) - \sum_i \lambda_i \cdot g_i(x)

with respect to each domain variable :math:`x_j` using the registered
derivation:

.. math::

    \frac{\partial L}{\partial x_j} = D(L)(x_j) = 0

This is equivalent to one higher Lasserre order in terms of bound
quality. The method ``_build_diff_kkt_moments()`` handles this
automatically when ``use_diff_kkt=True``. For multi-derivation
systems, the ``wrt`` parameter selects which derivation to use.
